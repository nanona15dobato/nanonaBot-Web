# 一時停止・再開と途中の変更

タスク詳細の「一時停止」で処理を止め、停止完了後に「対象の追加・除外」「タスク設定を編集」を使えます。操作はowner専用です。同じタスクIDで再開し、それまでの編集結果・編集ログを保持します。

## 操作の順番

1. 実行中のタスクで「一時停止」を押します。待機中なら直ちに停止します。
2. 「一時停止処理中」が消えるまで待ちます。ワーカーは保存中の編集・通信・先読みの終了を待って停止を確定します。保存済みの編集は取り消しません。
3. 「対象の追加・除外」でページ名を1行ずつ入力します。追加・除外・除外解除を一緒に保存できます（合計200ページまで）。ページ一覧にも未編集ページの除外ボタンがあります。
4. 必要なら「タスク設定を編集」を開きます。作成画面と同じフォームで置換ルール・名前空間・アカウント・要約・編集間隔・確認方法・失敗時の動作・purge設定を変更し、保存します。
5. 内容を確認して「再開する」を押します。保存だけでは処理を再開しません。

対象・設定の変更は待機中、停止完了後、緊急停止後、期限切れ後に利用できます。終了済み・中止済みタスクは変更できません。全体の緊急停止中は、必要に応じて全体停止も解除してください。

## 変更の適用範囲

| 操作 | 再開時の動作 |
|---|---|
| ページ追加 | 存在するページを明示的に追加し、全置換ルールを設定順に適用します。自動取得の名前空間指定より優先します。Templateは優先ウェーブ、通常ページは後続ウェーブ、固定対象タスクはウェーブ1で処理します |
| ページ除外 | 全ウェーブの編集と呼び出し先更新・残存purgeの対象から外します。既存の編集結果を巻き戻す操作ではありません |
| 除外解除 | 除外指定を解除します。元々手動追加されたページは追加対象に戻り、それ以外は自動取得で候補になる場合に処理します |
| 設定編集 | 新設定で未処理の対象を再取得し、最新本文から差分を作り直します |
| 変更なしで再開 | 保存済みの候補・purge進捗を使い、残りを処理します。準備済みの差分は最新版から再準備します |

対象・設定を保存すると、未処理ページの差分と承認を破棄し、ウェーブ1から候補を取り直します。purgeの計画・進捗も取り直すため、呼び出し先を再度purgeする場合があります。完了したページ（編集済み・変更なし・却下・失敗）は自動では再編集しません。変更後のルールを編集済みページにも適用したい場合は別タスクを作成してください。

失敗・変更なし・却下のページを明示的に「追加」すると、そのページだけを未処理としてやり直せます。編集済みページの再追加は拒否します。保存中にワーカーが落ちたなど、編集結果が不明なページは失敗として残し、先にウィキの履歴を確認します。

一括取り消しには元の版情報が必要なため、ページの追加はできません。固定対象の再試行・一括取り消しでは置換ルールを保持し、編集設定・確認設定などを変更できます。既存の旧ウェーブ構成を新しい全体ウェーブ構成へ切り替える操作ではありません。

複数タブから同時に変更した場合、先に保存された版だけを受け付けます。競合の表示が出たら画面を更新し、保存済みの内容を確認してから操作してください。

## 導入・更新

既存環境では、**新しいWeb・ワーカーを動かす前に**次を適用します。`db/schema.sql`の再読み込みだけでは既存のtasks列は追加されません。

```sql
USE s56574__nanona_bot;
SOURCE /data/project/nanonabot01/nanonaBot-Web/db/migrations/20261121_task_controls.sql;
SHOW COLUMNS FROM tasks WHERE Field IN ('pause_requested', 'worker_active', 'control_revision');
SHOW TABLES LIKE 'task_target_overrides';
```

Webとワーカーの両方を更新・再起動してから新しい操作を使ってください。旧ワーカーは停止要求を扱えません。稼働中のタスクがあれば、更新前に既存の緊急停止で処理が落ち着くのを確認します。ワーカーは1個で運用します。

```sh
toolforge webservice node20 restart
toolforge jobs restart nanona-bot-worker
```

追加列は停止要求、ワーカー処理中フラグ、変更の版番号です。`task_target_overrides`に追加・除外指定を保存します。ワーカー再起動時にも停止要求を維持します。

## 開発時の検証

`test/taskControls.test.js`は変更可能状態、版競合、履歴保持、対象の正規化、固定ルールを検証します。`test/pipeline.test.js`は確認中・保存中・先読み中の停止、`test/globalWaves.test.js`は変更後の対象取得とpurge再開、`test/recovery.test.js`は再起動時の停止維持を確認します。

ブラウザ検証は別途PlaywrightとChromiumを用意して実行します。API・ウィキ・DBはすべて模擬応答です。

```sh
PLAYWRIGHT_MODULE_PATH=/path/to/playwright node scripts/check-task-controls-ui.js
```

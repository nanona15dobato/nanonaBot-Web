## 共通の画面要素

| 要素 | 説明 |
|---|---|
| 上部バー | スクロールしても上に固定されます。ナビ（ダッシュボード・新規タスク・編集ログ・設定）は今いるページが強調されます。 |
| 緊急停止ボタン（赤） | いつでも押せます。確認ダイアログのあと、すべてのBot編集を止めます。→ [緊急停止](task-lifecycle.md#緊急停止) |
| 緊急停止中の警告帯 | 緊急停止中は全ページの上部に赤い帯が出ます（15秒ごとに確認）。オーナーは帯の「緊急停止を解除」から解除できます。 |
| ユーザーメニュー | 右上の人のアイコン。ログイン中のアカウント名・権限・ログアウト。 |
| 通知（トースト） | 操作の結果は画面右下に数秒表示されます（エラーは長めに表示）。 |
| 時刻の表示 | 「3分前」のように表示します。マウスを乗せると正確な日時が出ます。 |
| ページ名 | ウィキのページへのリンクです（別タブで開きます）。 |
| 自動更新 | 画面は自動で更新されます。ブラウザのタブを見ていない間は更新を止め、戻るとすぐ更新します。 |

## ダッシュボード

### 集計カード

「ワーカー」「実行中」「待機中」「要対応」「確認待ちページ」です。件数のカードを押すと、下のタスク一覧がその条件で絞り込まれます。

**ワーカー**のカードは、ワーカーの稼働状況（待機中／処理中 #タスク番号／緊急停止中／応答なし）を表示します。処理中のときに押すと、そのタスクを開きます。ワーカーからの応答が1分以上無い場合は、画面の上に「ワーカーからの応答がN秒ありません」と警告が出ます。その間タスクは処理されないので、Toolforgeで `toolforge jobs list`・`toolforge jobs logs` を確認し、必要ならワーカーのジョブを再起動してください。→ [ワーカーの稼働状況](task-lifecycle.md#ワーカーの稼働状況)

### 要対応

操作する人の対応を待っているタスクを、理由つきで先頭に並べます。古いタスクでも対応待ちなら載ります。

| 理由 | 次にすること |
|---|---|
| 確認待ちのページがN件あります | タスクを開いて承認・却下する |
| 失敗により一時停止しています | 実行ログ・ページ一覧で原因を確認し、「再開する」 |
| 緊急停止で中断しています | 緊急停止を解除してから「再開する」 |
| 無操作タイムアウトで期限切れになりました | 必要なら「再開する」（タイムアウトを取り直して続行） |
| 失敗したページがあります | 「失敗ページのみ再試行」（再試行タスクを作るまで、直近14日間表示） |
| タスクがエラーで終了しました | 実行ログを確認する |

### タスク一覧

新しい順に最大50件。状態（すべて／進行中／要対応／完了／中止・失敗）での絞り込みと、タスクID・アカウント・作成者での検索ができます。各行に進捗バーと確認待ち件数が出ます。

## 新規タスク作成

上から順に設定し、画面下部に固定された「タスクを作成してキューに投入」で送信します。

### Botアカウント

編集に使うBotアカウントを選びます。選ぶと、そのアカウントに保存しておいた既定値（編集設定・実行モード）が読み込まれます。

### 置換ルール

- 「ルールを追加」でルールを足し、種別を選んで入力します。種別ごとの意味は [置換ルールの種類](rule-types.md) を参照してください。
- ルールは**上から順に**適用されます。カード右上の矢印で並べ替えられます（番号は並び順で振り直されます）。
- 同じページに複数のルールが当てはまる場合は、まとめて1回の編集にします。
- 「Bot作業依頼から取り込む」で、Wikipedia:Bot作業依頼の `{{リンク修正依頼/改名}}` を読み込み、対応しているペアをまとめてルールにできます。→ [BOTREQからの取り込み](botreq.md)

### 編集設定

| 項目 | 説明 |
|---|---|
| Botフラグを付与 | 編集にBotフラグを付けます（最近の更新で非表示にできる）。 |
| 細部の編集にする | 編集を「細部の編集」にします。 |
| 要約欄 | 編集の要約。必須です。 |
| 編集間隔（秒・5以上） | 1件編集してから次の編集までの最低間隔。 |
| テンプレート使用ページの更新方法 | Category系ルールのウェーブ1後に、編集したテンプレートの使用ページのカテゴリ所属を更新する方法（null edit／purge）。→ [null edit と purge](task-lifecycle.md#null-edit-と-purgecategory系のウェーブ1のあと) |
| このアカウントのデフォルトとして保存 | 今の編集設定・実行モードを、選んでいるアカウントの既定値として保存します。 |

### 実行モード

| モード | 動き |
|---|---|
| 自動更新 | ページが確認待ちになってから「自動承認までの待機秒数」が経つと、自動で承認して編集します。待っている間に画面から承認・却下もできます。 |
| 確認待機（手動確認） | 画面で承認するまで編集しません。「無操作タイムアウト（時間）」の間に操作が無ければ、タスクは期限切れになります。 |

実行中でもタスク詳細画面から切り替えられます。

### 失敗時の挙動

| 選択肢 | 動き |
|---|---|
| 一時停止する | 失敗したページが出たらタスクを一時停止します。原因を確認して「再開する」で続行できます。 |
| スキップして続行する | 失敗したページは失敗のまま残し、次のページへ進みます。 |

一時的な失敗（編集競合・サーバーエラー等）は、失敗扱いにする前に自動で再試行します。→ [編集の失敗と再試行](task-lifecycle.md#編集の失敗と再試行)

### 送信前の確認

- 必須項目（改名元・改名先・要約欄など）や正規表現の誤りをチェックし、問題のあるルールを赤枠で示します。
- 問題が無ければ、内容の要約を確認ダイアログで表示します。「作成してキューに投入」でタスクが作られ、タスク詳細画面に移ります。
- 入力途中でページを離れようとすると、ブラウザが確認します。

## タスク詳細（確認・承認）

### 上部の進行パネル

タスクの今の状況に応じて、次のどれかを表示します（優先順）。

| 表示 | いつ出るか | できること |
|---|---|---|
| **確認待ち** | ワーカーがそのページの承認を待っているとき | 差分を見て「承認して編集」「却下」。自動更新モードでは自動承認までの残り時間がバーで出ます。 |
| **編集に失敗しました**（赤） | 画面で「編集中」だったページが失敗したとき | エラー内容と差分を確認し、「閉じて次へ」で次に進む |
| **次に編集するページ**（点線） | 前のページを編集中、または編集間隔をあけている間 | 先読み済みのページの差分を見て「前もって承認」「前もって却下」。前もって承認すると、確認待ちにならずにすぐ編集されます。 |
| **編集中** | 次のページがまだ準備できていないとき | 状況の確認（再試行待ちなら理由と残り時間が出ます） |

- パネルには「編集中: ○○（差分）」「直前に編集: ○○」の行も出ます。
- 編集が一時的に失敗して再試行を待っている間は「再試行待ち（1/3、約10秒後）: 理由」と表示されます。
- 手動確認モードで編集競合が起きた場合は、最新版で作り直した差分が「編集競合のため、最新版で作り直しました」という注意書きつきで確認待ちに戻ります。
- **キーボード**: `A` で承認、`R` で却下（入力欄にいるときやダイアログ表示中は無効）。

### タスク概要

- 状態・進捗バー（処理が確定したページ数／対象ページ数）
- ウェーブの進み具合（2・3ウェーブ構成のタスクのみ）
- ページの状態ごとの件数（押すとページ一覧をその状態で絞り込み）
- アカウント・確認モード（実行中は切り替え可）・失敗時の挙動・作成者・最終更新・このタスクの編集ログへのリンク
- 状態に応じたボタン（見出しの右）:

| ボタン | 表示される状態 | 動き |
|---|---|---|
| 再開する | 一時停止・緊急停止・期限切れ | 未処理のページから続行します（キューに戻ります）。 |
| 失敗ページのみ再試行 | 完了（一部失敗） | 同じルール・設定で、失敗したページだけを対象にした新しいタスクを作ります。 |
| 編集を一括で取り消す | 完了・完了（一部失敗）・失敗・中止・一時停止・緊急停止・期限切れ | このタスクの編集を編集前の版に戻す新しいタスクを作ります（要約欄と確認モードを選んでから作成）。→ [一括取り消し](task-lifecycle.md#一括取り消しリバート) |
| 複製 | 一括取り消しのタスク以外 | 同じアカウント・ルール・設定を入れたタスク作成画面を開きます（失敗ページの再試行タスクを複製したときは、元のルールの対象取得に戻ります）。内容を直してから作成できます。 |
| 中止 | 待機中・実行中・一時停止 | タスクを中止します。編集済みのページはそのまま残り、再開できません。 |
| 更新 | 常に | すぐ再読み込みします。 |

### タブ

| タブ | 内容 |
|---|---|
| ページ一覧 | 対象ページと状態。状態・ウェーブ・ページ名で絞り込めます。「差分」ボタンで各ページの差分をダイアログで確認できます（200件ずつ表示）。終わってから14日過ぎたタスクは、作業データを自動で削除するため表示されません（編集ログで確認できます）。 |
| 実行ログ | 対象取得・ウェーブの切り替わり・再試行・停止理由・人の操作（誰が承認/中止したか）など。新しい順。レベルで絞り込めます。 |
| 警告 | Category系で、`{{リダイレクトの所属カテゴリ}}` に旧カテゴリ名の記載があるのに構造的に確認できず自動編集しなかったページ。手動で確認してください。 |
| 設定内容 | このタスクの置換ルールと編集設定。 |

## 編集ログ

実際に編集した結果（成功・失敗）の恒久ログです。タスクのページ情報が消えた後も残ります。

- タスクID・ページ名（部分一致）・結果（成功／失敗）・表示件数（50／100／200）で検索します。Enterでも検索できます。
- 検索条件はURLに残ります（タスク詳細の「このタスクの編集ログを見る」からも開けます）。
- 成功した編集は「差分を見る」でウィキの差分を開けます。失敗はエラー内容が出ます。
- **CSVで書き出し**: 今の検索条件（表示件数の指定は使わず最大10000件）をCSVファイルで保存します。列は日時・結果・タスク・ウェーブ・ページ・名前空間・アカウント・版・編集前の版・要約・エラー・差分URL。Excelで開いても文字化けしないよう、UTF-8（BOMつき）で出力します。

## 設定

オーナーだけが使えます。各項目の横に、今の値の出どころ（画面で設定／環境変数／既定値・未設定）が出ます。「保存」で画面の値を保存し、環境変数より優先させます。

### 通知

通知先（Webhook・メール）と通知する出来事を設定します。「テスト送信」で、保存済みの設定で各通知先に実際に送り、結果を表示します。「環境変数の値に戻す」で画面の設定を消します。→ [通知](notifications.md)

### ワーカーの動作

実環境で動かしながら調整するための設定です。再起動は不要で、保存からワーカーへの反映は最大30秒です。

| 項目 | 既定値 | 範囲 | 目安 |
|---|---|---|---|
| 承認待ちの確認間隔（ミリ秒） | 500 | 100〜10000 | 承認してから編集が始まるまでの最大の遅れ。DBの負荷が気になるなら長くする |
| 一時的な失敗の再試行回数 | 3 | 0〜10 | → [編集の失敗と再試行](task-lifecycle.md#編集の失敗と再試行) |
| 1回目の再試行までの待ち時間（ミリ秒） | 10000 | 1000〜600000 | 2回目以降は倍々 |
| null edit / purge の間隔（ミリ秒） | 1000 | 0〜60000 | レート制限に当たるなら長くする |
| 作業データの保持日数 | 14 | 0〜3650 | → [作業データの自動削除](task-lifecycle.md#作業データの自動削除)。0で削除しない |

「環境変数・既定値に戻す」で、画面で保存した値を消します。

## 緊急停止だけ操作できる人の画面

管理者・拡張承認された利用者などは、ログインすると説明文と上部の「緊急停止」ボタンだけが表示されます。タスクの内容は見られません。緊急停止の解除はオーナーだけが行えます。

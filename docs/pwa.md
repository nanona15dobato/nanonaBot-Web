# PWA 第1段階

nanonaBot Webをホーム画面・デスクトップから起動できるようにする。既存のExpress/OOUIとCookie認証を使用し、操作はオンラインで行う。

## 対象機能

- アプリ名 `nanonaBot Web`、短縮名 `nanonaBot`。起動先 `/`、scope `/`、表示形式 `standalone`。
- 通常192/512px・maskable 512px・Apple用180pxのアイコン。
- ログイン画面と設定画面にインストール案内。緊急停止専用ユーザーにもホーム画面で案内する。
- インストールボタンは対応ブラウザがインストール可能と通知した場合だけ表示する。それ以外はブラウザメニューでの追加手順を表示する。
- 狭い画面のメニューをホーム・新規タスク・その他に整理。ノッチ・画面下端に余白を確保し、入力文字を16px以上にする。
- 既存のタスクカードを利用し、差分には左右表示と縦表示の切り替えを用意する。

## 通信と操作結果

- オフラインと判断できた時点ではAPI操作を送信しない。
- 通信が失敗した場合は表示内容が最新でない可能性を案内する。最終通信成功時刻は画面全体の更新時刻を保証しない。
- 変更操作の送信後に応答が途絶えた場合、成功・失敗を決めつけず、対象画面での確認を案内する。成功応答のJSON本文を読み取れなかった場合も同様に扱う。
- タスク作成の結果が不明なら作成ボタンを無効にし、タスク一覧へのリンクを表示する。
- 変更操作を自動再送せず、Background Syncやオフライン送信キューは使用しない。
- 再接続時には権限と表示内容を再取得する。画面へ戻った後、変更操作の前にも必要に応じて `/api/whoami` を確認する。
- ユーザー名・役割が表示時と変わった場合は変更操作を送らず、画面を開き直すよう案内する。サーバー側のリクエストごとの権限検査は引き続き実施する。
- PWAを閉じても、投入済みタスクはサーバー上で処理を続ける。

## キャッシュ

Service Worker `/sw.js` はルートから配信する。公開manifest・worker・静的ファイルはセッション処理より前に配信する。

| 対象 | 動作 |
|---|---|
| 個人情報を含まない `/static/offline.html` と4アイコン | 資格情報を付けずに事前保存 |
| 通常の画面遷移 | ネットワークから取得。通信失敗時だけ汎用オフライン画面を表示 |
| HTTP 403/500などの応答 | 元の応答を表示し、オフライン画面に置換しない |
| `/api/`・`/oauth/` | Service Workerは介入せず、保存しない |
| 変更操作・外部URL・JS/CSS | Service Workerは介入しない |

認証関連・動的HTML・APIにはHTTPの `Cache-Control: no-store` を付ける。JS/CSSは通常のHTTPキャッシュ規則に従う。利用者情報・差分・設定・認証情報をCache Storage、localStorage、IndexedDBへ永続保存しない。

## 更新と運用

- `/sw.js` とmanifestは `Cache-Control: no-cache` で再検証する。
- 待機中の更新があれば案内を表示し、利用者が確認してから新workerを有効にして再読み込みする。
- 変更操作の権限確認から応答本文の読み取りが終わるまで、更新ボタンを無効にする。
- 初回のService Worker有効化では強制再読み込みしない。
- Service WorkerはPWAをインストールしていない通常のブラウザ利用にも登録される。
- オフライン画面・アイコンを更新する際は `public/sw.js` の `CACHE_NAME` 末尾を変更する。古い同ツール用キャッシュだけを有効化時に削除する。
- アプリ版表示を変える場合は `public/js/pwa.js` の版番号も変更する。
- アイコンの原本は `scripts/generate-pwa-icons.py`。Python 3標準ライブラリのみで再生成でき、本番起動時の実行は不要。
- 不具合時にファイルを削除するだけでは登録済みworkerは解除されない。既存利用者への復旧には `/sw.js` からキャッシュ整理・登録解除を行うworkerを配信する必要がある。

既存の `frame-ancestors 'none'`・`X-Frame-Options: DENY` は継続する。

## 検証

自動テストは、manifest・画像、公開配信、HTTPキャッシュ制御、Service Workerの保存対象とフォールバック、権限変更時の送信抑止、結果不明時の再送防止、更新の明示的な適用を対象とする。実ブラウザのインストール可否や表示をNodeのテストだけで保証しない。

配備後に行う実機確認:

1. PCのChrome/Edge、AndroidのChrome、iPhone/iPadのSafariでインストールまたはホーム画面追加ができる。
2. インストール版でOAuthログイン・ログアウト・再起動ができる。外部認証から元の画面へ戻れる。
3. オーナーと緊急停止専用の利用者で、既存の権限に沿った画面を表示する。
4. 320px幅・横向き・ノッチのある端末でメニュー、緊急停止、フォーム、タスクカード、差分が操作できる。
5. 一度オンラインで起動した後、機内モードで汎用オフライン画面を表示する。APIや利用者データがCache Storageに存在しない。
6. テスト環境で変更操作の応答切断を再現し、自動再送やタスクの重複作成がない。復旧後に状態を照合できる。
7. テスト環境で別アカウントへの切り替え・権限変更を再現し、古い画面から変更操作を送信しない。
8. 新workerを配信したとき更新案内が出る。入力中に勝手に再読み込みせず、初回登録でも再読み込みしない。

Web Push、Wikimediaの通知・ウォッチリスト管理は後続段階とし、この段階では通知許可を求めない。
